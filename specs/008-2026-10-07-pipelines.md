## Context & Background

Today **Tarefas** holds independent task lists: a page of type `tasks` with `task_items` rows (title, done, position, trash). Notes create tasks in two more ways: margin actions (`source_actions` with `kind = 'task'`, spec 005) and inline `[ ]`/`[x]` checkbox lines tracked in `inline_tasks`. The home page (Caderninho) shows the latest note with its related graph, then a two-column row with pending tasks and today's reminders, then recent notes.

The user wants task lists replaced by a simple Trello: every list becomes a **pipeline**, a kanban board with configurable columns, and every task becomes a card with a description, comments, images and a movement history. Tasks created from notes join a pipeline too.

### Decisions settled with the user (2026-10-07)

1. A task list is renamed **pipeline**. A pipeline is a kanban with a title. The **Tarefas** section and its index keep their name and layout; clicking a pipeline opens the kanban full page.
2. A new pipeline has five columns: `Backlog`, `Ready to Dev`, `Doing`, `Review`, `Done` (English names, as written by the user).
3. Columns are configured per pipeline: add, remove, rename, reorder.
4. The **last column is the final column**: a card in it is complete, whatever the column's name. The final column shows a small "finalizada" pill, can be renamed, and can never be removed or moved; no column can be placed after it. New columns are added before it.
5. Removing a column that holds cards asks which column receives them.
6. A task is born at the top of the first column (`Backlog` by default).
7. A card shows the title, the creation date in small text and a comment-count pill ("3 comentários") when there are comments.
8. Cards move between columns and reorder inside a column by dragging; the order is stored. Every column change and every reorder is recorded in the task's movement history.
9. A task has a title, a rich-text description (same editor as notes: lists, tables, images), an optional free-text owner and `created_at`.
10. Clicking a card opens a modal with all task information, thumbnails of every image of the task (description and comments) and the comments.
11. Comments can be added, edited and removed. They use the same rich text, accept dropped images, show the creation date and "editado em …" after an edit. Removing asks for confirmation and does not go to the trash.
12. Task images are stored in `userData/pipelines/<pipelineId>/<NN>-<original name>`, `NN` being a sequential number inside the pipeline.
13. Existing task lists, list items, margin tasks and inline checkbox tasks are deleted. Reminders are not touched.
14. Creating a task from a note (selection, margin button, context menu or typing `[]` at a line start) opens the same **Nova tarefa** modal used in the kanban, with the title prefilled by the originating text; the user chooses the pipeline. The task is born at the top of the first column.
15. In the note, a task shows its column as a pill: the margin card shows the pipeline name and the column pill (no checkbox, no "Voltar à origem"); a line created with `[]` becomes a task line with the task title and the column pill. Cancelling the modal opened by `[]` removes the `[]` and leaves the line as plain text.
16. Existing `[ ]`/`[x]` lines in notes become plain text (the marker is removed, the text stays).
17. Trash gains two kinds, **Pipelines** and **Tarefas**. Restoring a task puts it back in its column, or in the first column if that column no longer exists.
18. Home strips, top to bottom: **Última nota + grafo** (one strip), **Kanban** (the most recently created pipeline of the active notebook, full width, interactive: drag cards, open the modal), **Lembretes**, **Últimas notas**. The pending-tasks section is removed: kanban and tasks are the same group. Every strip is foldable and the folded state is stored in SQLite. Without pipelines, the kanban strip shows "Nenhum pipeline ainda" and **+ Novo pipeline**.
19. The Tarefas index shows "3 finalizados de 12" for each pipeline.
20. Global search covers task titles, descriptions and comments.
21. Out of this specification: PDF export, Relacionados and categories for tasks.

## Problem Statement

### 1. Task lists only know "done" or "not done"
Lists are flat checkboxes. There is no intermediate status, no column layout, no per-task detail, no discussion and no record of how work moved.

### 2. Tasks live in three unconnected stores
List items (`task_items`), margin tasks (`source_actions`) and inline checkboxes (`inline_tasks`) each have their own lifecycle, trash and home rendering. A task created from a note never joins a list.

### 3. Tasks cannot carry context
A task has only a title. Specifications, tables and photos have to live in a separate note.

---

## Solution

1. A new **Pipelines** bounded context owns pipelines (the `tasks` pages), their columns, tasks, comments, movement history and task images.
2. The pipeline page replaces the list page with a kanban; the task modal and the new-task modal are shared by the kanban, the home strip and the note.
3. The note editor is refactored so one page can host several independent editor instances (note body, task description, comment), with the same block model.
4. Margin tasks and `[]` lines become links from a note to a pipeline task; reminders stay in `source_actions`.
5. The home page becomes a stack of foldable strips with the kanban strip.
6. A one-time migration deletes list items, margin tasks and inline tasks and turns checkbox lines into plain text.

---

## Practical Gains & Operational Outcomes

1. **Task workflow**:
   - *Before*: a task is pending or done.
   - *Now*: a task moves through user-defined columns, and the history shows when and where it moved.
2. **One task model**:
   - *Before*: three task stores with different rules.
   - *Now*: every task is a pipeline task; notes only link to it.
3. **Context on the task**:
   - *Before*: a title only.
   - *Now*: rich description, comments and images, organised on disk by pipeline.

## Architecture Gate

### 1. Bounded Context & Ubiquitous Language
- **Context**: Pipelines.
- **Package Ownership**:
  - `src/main/pipelines/domain/`: the pipeline aggregate (`pipeline.cjs`: columns, final-column rule, card ordering), the task entity (`task.cjs`), comments (`comment.cjs`), movement history (`movement.cjs`), image naming (`task-image.cjs`) and ports (`ports.cjs`).
  - `src/main/pipelines/application/`: one use case per file: `open-pipeline`, `add-column`, `rename-column`, `move-column`, `remove-column`, `create-task`, `update-task`, `move-task`, `trash-task`, `restore-task`, `purge-task`, `add-comment`, `edit-comment`, `remove-comment`, `attach-task-image`, `read-task-image`, `list-pipelines`.
  - `src/main/pipelines/infrastructure/`: the SQLite repository and migration (`sqlite-pipeline-repository.cjs`), the image file store (`pipeline-image-files.cjs`).
  - `src/main/pipelines/presentation/ipc.cjs`: IPC handlers with payload validation; the `caderno-pipeline` protocol handler.
  - `src/main/pipelines/compose.cjs`: wiring, like boards.
  - `src/renderer/pipelines/`: kanban view, column menu, drag and drop, card, task modal, new-task modal, comment list, home strip, note task line and margin task card.
  - `src/renderer/` editor files: the block editor is refactored into an instance API (see Implementation Decisions 6); ownership stays with the editor.
- **Ubiquitous Terms**:
  - `Pipeline`: a page of type `tasks`; a kanban with a title, columns and tasks.
  - `Coluna` / column: an ordered stage of a pipeline.
  - `Coluna final` / final column: the last column; tasks in it are complete.
  - `Tarefa` / task: a card of a pipeline.
  - `Movimentação` / movement: a history entry for a task (created, column change, reorder).
  - `Comentário` / comment: rich text attached to a task.
  - `Imagem da tarefa` / task image: a file in the pipeline folder referenced by a task description or comment.
  - `Linha de tarefa` / task line: a note block that shows a linked task.
  - `Faixa` / strip: a foldable section of the home page.

### 2. Aggregate Root & State Transitions
- **Aggregate**: `Pipeline` (`noteId`, `columns[]`, `tasks[]` ordered per column). Tasks, comments, movements and images belong to it.
- **Page lifecycle** reuses notes: `active → trashed → active` or `trashed → purged`. Purging a pipeline deletes its columns, tasks, comments, movements, images and its image folder.
- **Task lifecycle**: `active → trashed → active` (restore) or `trashed → purged`. Purging a task deletes its comments, movements and images.
- **Task status** is derived: complete when its column is the final column.
- **Invariants**:
  1. A pipeline has at least two columns (one entry column plus the final one), so a new task is never born complete. The final column is always the last position.
  2. The final column cannot be removed or moved; a column cannot be added after it.
  3. Column names are 1–60 characters, trimmed; names need not be unique.
  4. Positions inside a column are contiguous from 0 with no duplicates.
  5. A new task is inserted at position 0 of the first column, shifting the others.
  6. Every column change and every reorder appends one movement in the same transaction as the change; a move to the same column and the same position is a no-op and records nothing.
  7. Removing a column moves its cards to the chosen column (appended at the end, in their order) and records one movement per card.
  8. Task title: 1–500 characters. Owner: 0–120 characters. Description and comment documents follow the note document limits.
  9. Image file names are `NN-<sanitised original name>`; `NN` is the pipeline's next sequence number (two digits minimum, growing as needed); the sanitised name keeps letters, digits, `-`, `_` and `.`, is at most 80 characters and keeps a whitelisted image extension.
  10. A task image is deleted from disk when no description or comment of its task refers to it after a save, and when its task or pipeline is purged.
  11. Movements are append-only and store the column names at the time of the move.

### 3. Commands, Queries & Domain Ports
```javascript
/** @typedef {{ id: string, name: string, position: number, final: boolean }} Column */
/** @typedef {{ id: string, pipelineId: string, columnId: string, position: number, title: string, owner: string, createdAt: string, updatedAt: string, commentCount: number, source: { noteId: string } | null }} TaskCard */
/** @typedef {{ load(pipelineId: string): Pipeline|null, save(change: PipelineChange): void, task(taskId: string): Task|null, nextImageNumber(pipelineId: string): number }} PipelineRepositoryPort */
/** @typedef {{ write(pipelineId: string, fileName: string, bytes: Buffer): void, read(pipelineId: string, fileName: string): Buffer, remove(pipelineId: string, fileName: string): void, removeFolder(pipelineId: string): void }} PipelineImageStorePort */
/** @typedef {{ now(): string, id(): string }} ClockPort */
/** Query: openPipeline({ pipelineId }) -> { pipelineId, title, columns: Column[], tasks: TaskCard[] } */
/** Query: openTask({ taskId }) -> { ...TaskCard, description: EditorDocument, comments: Comment[], movements: Movement[], images: { imageId, url }[] } */
/** Command: addColumn({ pipelineId, name }) | renameColumn({ columnId, name }) | moveColumn({ columnId, toPosition }) | removeColumn({ columnId, targetColumnId }) */
/** Command: createTask({ pipelineId, title, owner, description, source? }) -> { taskId } */
/** Command: updateTask({ taskId, title?, owner?, description? }) */
/** Command: moveTask({ taskId, columnId, position }) */
/** Command: trashTask | restoreTask | purgeTask ({ taskId }) */
/** Command: addComment({ taskId, document }) | editComment({ commentId, document }) | removeComment({ commentId }) */
/** Command: attachTaskImage({ taskId, name, mime, dataURL }) -> { imageId, url } */
```
- **Domain events**: `TaskMoved { taskId, from, to }` and `TaskChanged { taskId }`; both refresh the snapshot so note pills, home and index counts update.

| `task:attach-image` | `taskAttachImage(input)` | `{ taskId, name, mime, dataURL }` | `{ imageId, url }` | `Use uma imagem PNG, JPEG, GIF ou WebP de até 15 MB.` |
| `notebook:purge` (**changed**) | `purge('task', id)` | kind `item` replaced by `task` | snapshot | `Este item não está na lixeira.` |
| `notebook:action` (**changed**) | `action(…)` | adds `home:fold { strip: 'latest'\|'pipeline'\|'reminders'\|'notes', folded: boolean }`; removes `item:*`, `inline:toggle`, `source:toggle`; `source:create` accepts only `kind: 'reminder'` | snapshot | `Faixa inválida.`, `Tipo de ação inválido.`, `Ação inválida.` |

- Every handler accepts only the main window's `webContents` and validates `unknown → validated input → command` in `presentation/ipc.cjs`: id formats; the pipeline is a non-trashed page of type `tasks` for writes; the task and comment belong to an active pipeline; enum values; documents go through the shared editor-document normaliser; `source.noteId` is a non-trashed note of type `notes`; images follow the board image rules (mime whitelist, `dataURL` prefix match, ≤ 15 MB decoded).
- Write channels answer with the full snapshot, like `notebook:action`, so every surface (kanban page, home strip, margin, task lines) re-renders from one state.
- **Protocol** `caderno-pipeline://<pipelineId>/<imageId>` serves task images (registered as a privileged standard scheme; the CSP `img-src` allows it). It resolves the id through SQLite to a file inside `userData/pipelines/<pipelineId>/` and rejects anything else (no raw paths, no traversal), like `caderno-media`.

## Implementation Decisions

1. **Schema** (explicit migration, no compatibility shims):
   - `pipeline_columns(id TEXT PRIMARY KEY, note_id TEXT NOT NULL REFERENCES notes(id) ON DELETE CASCADE, name TEXT NOT NULL, position INTEGER NOT NULL, created_at TEXT NOT NULL, updated_at TEXT NOT NULL)`.
   - `pipeline_tasks(id TEXT PRIMARY KEY, note_id TEXT NOT NULL REFERENCES notes(id) ON DELETE CASCADE, column_id TEXT NOT NULL REFERENCES pipeline_columns(id), position INTEGER NOT NULL, title TEXT NOT NULL, owner TEXT NOT NULL DEFAULT '', description TEXT NOT NULL DEFAULT '[]', description_text TEXT NOT NULL DEFAULT '', source_note_id TEXT REFERENCES notes(id) ON DELETE SET NULL, source_origin TEXT, created_at TEXT NOT NULL, updated_at TEXT NOT NULL, deleted_at TEXT)`.
   - `pipeline_comments(id TEXT PRIMARY KEY, task_id TEXT NOT NULL REFERENCES pipeline_tasks(id) ON DELETE CASCADE, document TEXT NOT NULL, text TEXT NOT NULL, created_at TEXT NOT NULL, updated_at TEXT NOT NULL, edited_at TEXT)`.
   - `pipeline_movements(id INTEGER PRIMARY KEY AUTOINCREMENT, task_id TEXT NOT NULL REFERENCES pipeline_tasks(id) ON DELETE CASCADE, kind TEXT NOT NULL CHECK(kind IN ('create','column','reorder','restore')), from_column TEXT, to_column TEXT NOT NULL, from_position INTEGER, to_position INTEGER NOT NULL, at TEXT NOT NULL)` (column names, not ids).
   - `pipeline_images(id TEXT PRIMARY KEY, note_id TEXT NOT NULL REFERENCES notes(id) ON DELETE CASCADE, task_id TEXT NOT NULL REFERENCES pipeline_tasks(id) ON DELETE CASCADE, number INTEGER NOT NULL, file TEXT NOT NULL, mime TEXT NOT NULL, bytes INTEGER NOT NULL, UNIQUE(note_id, number))`.
   - `note:create` with type `tasks` inserts the five default columns in the same transaction.
   - Migration: delete all `task_items`, `inline_tasks` and `source_actions` rows with `kind = 'task'` and drop `task_items` and `inline_tasks`; existing `tasks` pages become pipelines with the default columns; `check` blocks in note documents become `paragraph` blocks and `[ ]`/`[x]` prefixes are removed from note bodies.
2. **Note links**: a margin task stores `source_note_id` and `source_origin` (the same origin shape as `source_actions`: text parts or cut) and keeps the dashed highlight in the note, green when the task is in the final column. A `[]` task line is a new editor block type `task` `{ id, taskId, title }`; `title` is a snapshot used when the task is gone. Reminders keep `source_actions` unchanged.
3. **Snapshot**: `notebook:state` carries, per pipeline, the columns and task cards (no descriptions or comments), plus per task the plain text of description and comments for global search. Descriptions, comments, movements and images load only through `task:open`.
4. **Home**: the kanban strip uses the snapshot of the most recently created non-trashed pipeline of the active notebook. Strip fold state is stored in `settings` (`home_fold_<strip>`). The kanban strip appears only on today's page, like the latest-note strip; past daily pages are read-only and show reminders and recent notes. Daily snapshots stop recording tasks.
5. **Drag and drop**: pointer-based dragging with a placeholder, persisted through `task:move` on drop. A failed move reverts the board and shows the existing error notice.
6. **Editor instances**: the block editor today assumes one `#note-body`. It is refactored into an instance API (`createEditor(host, options)`) so the note page, the task description and each comment editor are independent hosts with their own selection, slash menu, formatting menu and history. Options turn off margin actions, categories and hashtags outside notes. This refactor is the first implementation step, guarded by the existing editor smoke tests.
7. **Undo**: the description and comment editors have their own history. Card moves and column changes are not undoable (the history records them).
8. **Modal**: one task modal component serves the kanban, the home strip, note task lines and margin cards. Edits to title, owner and description autosave 400 ms after the last change and flush on close and on quit.
9. **Search**: the global search gains the result kind "Tarefa"; opening it opens the pipeline and the task modal.
10. **File limits**: every file has one responsibility and stays at or under 250 lines.
11. **Dependency direction**: the domain imports nothing from Electron, `node:sqlite`, `fs` or the DOM.

## Follow-up Decisions (settled with the user, 2026-10-07)

1. **Minimum columns**: a pipeline keeps at least two columns; the last non-final column cannot be removed.
2. **Pipeline choice from a note**: the new-task modal lists the pipelines of the note's notebook and preselects the most recently created. With none, it shows "Crie um pipeline primeiro" and **+ Novo pipeline**.
3. **Deleted tasks in a note**: a trashed task shows its title with a "na lixeira" pill; a purged task shows the stored title as struck-through text. The margin × sends the task to the trash.
4. **`[]` scope**: `[]` creates a task only at the start of a plain paragraph line, not inside tables, lists or quotes.
