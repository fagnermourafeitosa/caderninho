## Context & Background

Caderninho has three page types (`notes`, `tasks`, `reminders`) stored in the `notes` table, plus Mermaid diagrams as text blocks inside notes (spec 002). There is no free-form visual space: people who plan with sticky notes, arrows and loose shapes on a canvas (Miro, Mural) have nowhere to do it in the app.

This specification adds a fourth page type, **Quadro** (board): an infinite canvas with shapes, post-its, connectors, frames, images and free text. It is built on the open-source Excalidraw component, wrapped by Caderninho's own tool rail and contextual toolbar so it looks like the rest of the paper notebook.

The product register (`docs/PRODUCT.md`) keeps one headline idea: notes that turn into tasks without losing context. Boards are a supporting page type. They are designed so a later specification can anchor tasks and reminders to a board element (see Q5 below), but this specification does not do it.

### Feasibility spike (2026-10-06)

Excalidraw 0.18.1 was bundled with esbuild and rendered with a scene resembling the mockup. The spike found:

- The package is ESM-only with React as a peer dependency, so it cannot be copied as a single file like Mermaid; it needs a bundle step.
- Fonts load from a CDN unless `window.EXCALIDRAW_ASSET_PATH` points at local files.
- The selection outline colour is read from the CSS variable `--color-selection`, so it can be ink.
- Frames are drawn on the canvas with fixed constants: `#bbb` 2px outline, 8px radius, no fill, name in `#999` system font. Not reachable by API or CSS.
- There is no folded-corner or shadow shape, image elements have no border, and the selection box is solid with rounded handles.
- The imperative API exposes `updateScene`, `setActiveTool`, `addFiles`, `getSceneElements`, `getAppState`, `onChange`, `onScrollChange` and `scrollToContent`, but **no undo/redo**. The native footer (zoom and undo/redo) is DOM and can be restyled with CSS.
- A bound label inherits the container's `strokeColor`, so a post-it with a transparent outline must set its text colour explicitly or the text disappears.
- Built-in letter shortcuts: V selection, H hand, R rectangle, D diamond, O ellipse, A arrow, L line, P/X pencil, T text, E eraser, F frame, K laser, I eyedropper. Image has only the numeric key 9. `N` is unbound.
- Excalidraw ships a `pt-BR` locale.

## Problem Statement

### 1. No free-form visual planning space
Notes are linear text. Mermaid diagrams (spec 002) are generated from code, so they cannot be sketched by hand, rearranged by dragging or mixed with sticky notes and images.

### 2. An embedded canvas library brings UI and behaviour that contradict the app
Out of the box Excalidraw shows its own purple toolbar, a properties side panel, a library button, collaboration and cloud links, English hints, a dark-theme toggle and remote fonts. These break the paper design (`docs/DESIGN.md`), the offline rule (`AGENTS.md`, outbound network) and the CSP.

### 3. Boards need to persist and integrate like any page
A board must survive quit, move to trash and back, belong to a notebook, carry categories, be found by search and keep its images in the shared media store without leaking orphans.

---

## Solution

1. Add the page type `boards` ("Quadro"/"Quadros") with its own sidebar row, index and page view.
2. Vendor Excalidraw 0.18.1 with React into one bundle together with Caderninho's board UI, built by a new vendoring script, with fonts served locally.
3. Hide every native Excalidraw control except the canvas and the footer. Replace them with Caderninho components driven by the imperative API: the **tool rail**, the **contextual bar** and its **popovers**. Restyle the native footer with CSS.
4. Persist the scene in a new `boards` table owned by the main process. The page's `notes.body` holds the plain text extracted from the scene, so search, related pages and the trash keep working on one column.
5. Store images through the existing media store, referenced from a new `board_files` table that orphan collection takes into account.
6. Export PNG and SVG through a save dialog in the main process.

---

## Practical Gains & Operational Outcomes

1. **Visual planning**:
   - *Before*: only linear text, checklists and code-generated diagrams.
   - *Now*: post-its, shapes, connectors that follow their shapes, frames, images and free text on an infinite canvas.
2. **Design coherence**:
   - *Before*: an embedded library would bring its own purple, English, cloud-linked UI.
   - *Now*: the board reads as a page of the same paper notebook, matching the reference images.
3. **Data integrity**:
   - *Before*: no board persistence.
   - *Now*: transactional scene saves with version checks, a flush on quit, trash and restore, and deduplicated media with collection that sees board references.

## Architecture Gate

### 1. Bounded Context & Ubiquitous Language
- **Context**: Boards.
- **Package Ownership**:
  - `src/main/boards/domain/`: the board aggregate (`board.cjs`), scene validation and normalisation (`scene.cjs`), text extraction (`scene-text.cjs`) and ports (`ports.cjs`).
  - `src/main/boards/application/`: one use case per file (`open-board.cjs`, `save-board.cjs`, `read-board-file.cjs`, `attach-board-image.cjs`, `save-board-thumbnail.cjs`, `read-board-thumbnail.cjs`, `export-board.cjs`).
  - `src/main/boards/infrastructure/`: the SQLite repository and schema migration (`sqlite-board-repository.cjs`), the media-store adapter (`media-board-files.cjs`) and the save-dialog adapter (`dialog-export-target.cjs`).
  - `src/main/boards/presentation/ipc.cjs`: IPC handlers with payload validation.
  - `src/renderer/boards/`: board UI source (React): mount entry, tool rail, contextual bar, popovers, post-it tool, background grid sync, save scheduler, theme CSS. It is bundled into a generated file loaded by `index.html` and exposes one global, `window.CaderninhoBoard.mount(element, options)` / `unmount()`.
  - `scripts/vendor-excalidraw.cjs`: builds the bundle and copies the Excalidraw fonts into `src/renderer/vendor/`. Runs in `prestart`, `prepackage` and `pretest:app`, like the Mermaid script.
- **Ubiquitous Terms**:
  - `Quadro` / board: a page of type `boards`.
  - `Cena` / scene: the board's element list plus viewport.
  - `Elemento` / element: one Excalidraw element. Its `id` is stable for life (future action origin, Q5).
  - `Post-it`: a rectangle with bound text, created with the post-it defaults.
  - `Frame`: an Excalidraw frame element.
  - `Arquivo do quadro` / board file: an image referenced by an element's `fileId`, stored as a media blob.
  - `Barra de contexto`: the floating contextual bar.
  - `Trilho`: the tool rail.

### 2. Aggregate Root & State Transitions
- **Aggregate**: `Board` (`noteId`, `version`, `elements`, `viewport`, `files`, `thumbnail`), owned by the page (`notes` row, type `boards`).
- **Page lifecycle** reuses notes: `active → trashed → active` (restore) or `trashed → purged`.
- **Scene version**: starts at 0. Each accepted save sets `version = previous + 1`. A save whose `baseVersion` differs from the stored version is rejected as stale.
- **Invariants**:
  1. Element types are limited to `rectangle`, `diamond`, `ellipse`, `arrow`, `line`, `freedraw`, `text`, `image`, `frame`. `embeddable`, `iframe` and `magicframe` are rejected.
  2. Every element's `link` is normalised to `null` (no element hyperlinks in v1).
  3. Every image element's `fileId` refers to a `board_files` row of the same board.
  4. At most 10,000 elements and 8 MB of serialised scene per board.
  5. `notes.body` of a board always equals the text extracted from its last saved scene (text elements, bound labels, frame names), joined by newlines.
  6. A save commits the `boards` row, the `board_files` changes and `notes.body`/`updated` in one transaction.

### 3. Commands, Queries & Domain Ports
```javascript
/** @typedef {{ elements: object[], viewport: { scrollX: number, scrollY: number, zoom: number } }} Scene */
/** @typedef {{ load(noteId: string): Board|null, save(board: Board, extractedText: string): void, files(noteId: string): BoardFile[] }} BoardRepositoryPort */
/** @typedef {{ put(bytes: Buffer, mime: string): { blobId: string }, read(blobId: string): { bytes: Buffer, mime: string } }} MediaStorePort */
/** @typedef {{ choose(suggestedName: string, format: 'png'|'svg'): Promise<string|null>, write(target: string, bytes: Buffer): Promise<void> }} ExportTargetPort */
/** Query: openBoard({ noteId }) -> { noteId, version, scene, files: [{ fileId, mime }] } */
/** Command: saveBoard({ noteId, baseVersion, scene }) -> { version, updated } */
/** Query: readBoardFile({ noteId, fileId }) -> { fileId, mime, dataURL } */
/** Command: attachBoardImage({ noteId, fileId, mime, dataURL }) -> { fileId } */
/** Command: saveBoardThumbnail({ noteId, png }) -> void */
/** Query: readBoardThumbnail({ noteId }) -> { png } | null */
/** Command: exportBoard({ noteId, format, name, data }) -> { saved: boolean } */
```
- **Domain events**: `BoardSaved { noteId, version }` (triggers the related-pages reschedule) and `BoardImageAttached { noteId, fileId, blobId }`.

### 4. IPC Contract & External Input Validation
| Channel | Preload function | Payload | Result | Errors |
| :--- | :--- | :--- | :--- | :--- |
| `board:open` | `boardOpen(noteId)` | `noteId: string` | `{ noteId, version, scene, files }` | `Quadro não encontrado.` |
| `board:save` | `boardSave(input)` | `{ noteId, baseVersion: int ≥ 0, scene: Scene }` | `{ version, updated }` | `Quadro inválido.` (shape, type or limit), `O quadro mudou em outra janela. Recarregue.` (stale), `Quadro não encontrado.` |
| `board:file` | `boardFile(input)` | `{ noteId, fileId }` | `{ fileId, mime, dataURL }` | `Imagem não encontrada.` |
| `board:attach-image` | `boardAttachImage(input)` | `{ noteId, fileId, mime, dataURL }` | `{ fileId }` | `Use uma imagem PNG, JPEG, GIF ou WebP de até 15 MB.` |
| `board:thumbnail` | `boardThumbnail(input)` | `{ noteId, png: dataURL }` | `null` | `Miniatura inválida.` |
| `board:thumbnail-read` | `boardThumbnailRead(noteId)` | `noteId: string` | `{ png: dataURL } \| null` | `Quadro não encontrado.` |
| `board:export` | `boardExport(input)` | `{ noteId, format: 'png'\|'svg', name: string ≤ 160, data: dataURL\|string }` | `{ saved }` | `Exportação inválida.` |
| `notebook:action` (**changed**) | `action('note:create', …)` | the type enum gains `'boards'` | unchanged | unchanged |

- Every handler accepts only the main window's `webContents` and validates `unknown → validated input → command` in `presentation/ipc.cjs`:
  - `noteId` and `fileId` match the existing id format;
  - `noteId` refers to a page of type `boards`, not trashed, for writes;
  - the scene is a plain object with an `elements` array and a finite viewport, with `zoom` clamped to 0.1–30;
  - element types are on the whitelist, and the element count and byte limits hold;
  - images: `mime` is one of `image/png`, `image/jpeg`, `image/gif`, `image/webp`, the `dataURL` prefix matches it, and the decoded size is ≤ 15 MB;
  - thumbnails are PNG and ≤ 256 KB;
  - exports are ≤ 50 MB and the format is on the enum. SVG is written as text after a check that it starts with `<svg`.
- The board never reaches the network: fonts are local, there is no `validateEmbeddable`, embeds are disabled and links are stripped.
- **CSP**: unchanged unless Excalidraw needs `blob:` in `img-src` or `worker-src`. Any addition is limited to `blob:` and recorded under "Implementation Record" with its reason.

## Implementation Decisions

1. **Schema** (explicit migration, no compatibility shims):
   - Rebuild `notes` so `type` accepts `'boards'`, using the table-rebuild pattern already used for `cuts`.
   - Create `boards(note_id TEXT PRIMARY KEY REFERENCES notes(id) ON DELETE CASCADE, version INTEGER NOT NULL, scene TEXT NOT NULL, thumbnail BLOB, updated_at TEXT NOT NULL)`.
   - Create `board_files(note_id TEXT NOT NULL REFERENCES notes(id) ON DELETE CASCADE, file_id TEXT NOT NULL, blob_id TEXT NOT NULL REFERENCES media_blobs(id), PRIMARY KEY(note_id, file_id))`.
   - `note:create` with type `boards` inserts the empty `boards` row in the same transaction.
2. **Media**: images reuse the media store and its SHA-256 dedup. Orphan collection keeps any blob referenced by `cuts` **or** `board_files`. A `board_files` row whose `fileId` no longer appears in the saved scene is deleted on save, in the same transaction.
3. **Snapshot**: `notebook:state` does not carry scenes. Board pages appear in the snapshot like other pages (title, body = extracted text, dates, categories, notebook) plus `hasThumbnail`. The scene loads only through `board:open`.
4. **Saving**: the renderer schedules a save 400 ms after the last `onChange` that altered elements or the viewport, ignoring selection-only changes. One save is in flight at a time. On page switch, window close and quit, the pending save is flushed through the existing quit flush before the window closes. A failed save uses the existing save-error notice. The thumbnail (320×200 PNG via `exportToBlob`) is sent at most every 5 s after a successful save.
5. **Undo**: inside the canvas, ⌘Z/⇧⌘Z and the footer buttons use Excalidraw's own history. The page history (`undo.js`) keeps owning title and category edits and must not intercept keys whose target is inside the board canvas. The native Edit menu routes undo/redo to the board when the canvas has focus.
6. **Keyboard**: Excalidraw letter shortcuts work while the canvas has focus. **N** is registered (`registerAction` with a `keyTest`) to activate the post-it tool. App-wide shortcuts (search, Mais menu items, navigation) keep working. ⌘F inside the canvas opens Caderninho's global search, not Excalidraw's.
7. **Hidden native UI**:
   - `UIOptions` disables export, save, load, background colour and theme;
   - CSS hides the top toolbar, the properties panel, the hamburger menu, the library button, the help button and the hint line;
   - the welcome screen is replaced by nothing (an empty canvas with the rail);
   - `langCode="pt-BR"` and `theme="light"`.
8. **Paste and drop**: pasting or dropping an image file creates an image element through `board:attach-image`. Pasting text creates a text element (native behaviour). Pasting Excalidraw clipboard data keeps working, and the main process normalises it on save (whitelist, link stripping).
9. **Full screen**: "Tela cheia do quadro" in Mais and in the native **Nota** menu (⇧⌘F) switches to the full-screen reference image. Esc, the same shortcut or **Sair da tela cheia** leaves it. Esc first cancels an Excalidraw interaction in progress (text editing, active tool); only an idle canvas leaves full screen. The state is not persisted.
10. **Mais menu on a board**: Exportar PNG, Exportar SVG, Tela cheia do quadro, Relacionados, a separator, Mover para a lixeira. Adicionar mídia and Exportar PDF are not offered.
11. **Search and related pages**: they read `notes.body` (the extracted text), unchanged. The search result kind label is "Quadro".
12. **Categories**: manual only (header picker). Hashtags written inside board text do **not** create inline categories.
13. **Home**: the "latest updated note" preview ignores boards. Recent pages lists include boards with their title.
14. **Index**: the Quadros index reuses the notes index code path and adds the thumbnail, exactly as the index reference images show. A thumbnail is served as `data:` from the snapshot's `hasThumbnail` through `board:thumbnail-read` (see IPC), loaded lazily per visible row.
15. **Bundle**: the generated bundle and the copied fonts are build outputs (git-ignored), produced by `scripts/vendor-excalidraw.cjs`. Production code never requires `scripts/`. Packaged paths resolve inside the asar.
16. **Dependencies**, pinned exactly: `@excalidraw/excalidraw` 0.18.1, `react`, `react-dom` (19.x, same version) and `esbuild`, all as devDependencies.
17. **Patching Excalidraw is prohibited** (no edits to the bundle, no `patch-package`, no fork). Customisation is limited to its props, imperative API, CSS and Caderninho components.
18. **File limits**: every file has one responsibility and stays at or under 250 lines. The rail, the bar, each popover and the save scheduler are separate files.
19. **Dependency direction**: the domain imports nothing from Electron, `node:sqlite`, `fs` or the DOM. Renderer components hold no persistence or validation rules beyond UI state.

## Testing Decisions

### Unit Tests (`tests/boards.test.cjs`)
- Scene validation: whitelisted types pass; `embeddable`, `iframe`, `magicframe` and unknown types are rejected; `link` is normalised to `null`; the element-count and byte limits are enforced; a non-finite viewport is rejected and zoom is clamped.
- Text extraction: text elements, bound labels and frame names come out in scene order; deleted elements are excluded.
- Version: a stale `baseVersion` is rejected; an accepted save increments the version.
- Image validation: mime whitelist, data URL prefix mismatch, size over 15 MB.

### Integration Tests (`tests/boards-store.test.cjs`, temporary data directory)
- `note:create` with `boards` creates the `notes` and `boards` rows atomically.
- A save updates `boards`, `notes.body`, `notes.updated` and `board_files` in one transaction; a failure rolls back all of them.
- Trash, restore and purge of a board; purge cascades `boards` and `board_files`.
- Orphan collection keeps blobs referenced by `board_files` and deletes them once no cut or board refers to them; the same image in a note and a board is stored once.
- Migration: an existing database gains the `boards` type and tables without losing notes.

**Decisions and deviations**
1. **Bar actions reuse Excalidraw's own actions (needs approval).** The 0.18.1 imperative API has no `executeAction`. Plain property changes (colours, fill pattern, opacity, width, line style, hand-drawn, corners, heads, line curvature, text colour and alignment) go through `updateScene`. Actions that need Excalidraw's logic (duplicate, delete, layer order, group, lock, copy/paste style, align left/top, distribute, font family and size, arrow sharp/curve/elbow) are triggered through Excalidraw's own keyboard bindings dispatched to its canvas, or through its properties panel, which stays mounted but is never visible (CSS). "Em frame" builds the frame with `convertToExcalidrawElements` + `updateScene`. No Excalidraw code is changed.
2. **Narrow windows use Excalidraw's mobile layout (needs approval).** Excalidraw switches layout when the canvas is narrower than 730 px (or shorter than 500 px and narrower than 1000 px). At the app's default 820 px window the canvas is about 520 px wide, so the native footer shows Excalidraw's mobile controls instead of the zoom group of the reference image. The bar still works there (it opens Excalidraw's mobile shape menu off-screen when needed). The smoke scenario and the visual comparison use 1280×860, the size of the reference images.
3. **Post-it tool (needs approval).** N or the rail button arms an Excalidraw custom tool; the next press on the canvas drops the post-it centred there and starts typing. A label inside a shape with a transparent outline is inked `#303025` as soon as it appears.
4. **Freehand strokes show no contextual bar (needs approval)**: the specification defines none.
5. Popover details read from the toolbar image: the width and line-style buttons open the same popover (Espessura + Estilo da linha); "Vazio" sets a transparent fill; the stroke swatch is a ring in the stroke colour (edge colour when transparent); the shape bar's "Aa M" popover offers font and size for the shape's label.
6. Saved scenes include Excalidraw's deleted elements (its undo can bring them back), so `notes.body` excludes them and a board file stays while any element in the scene, deleted or not, references it.
7. New boards are created without a title (shown as "Sem título"), matching the index image.
8. **Flush on close/quit**: a `beforeunload` handler in the renderer defers the window close while a board save is pending, saves, then closes the window. No IPC channel was added. Verified for window close; the quit path relies on the same close.
9. Board images go through `MediaStore.image`, which normalises every raster to PNG: this is what deduplicates a board image with the same image in a note, but GIF animation and JPEG compression are not kept.
10. `note:update` refuses `body`/`editorDoc` for a board ("O texto do quadro vem dos elementos do quadro."), enforcing invariant 5.
11. Recent pages: boards appear in the daily overview's recent list (under its existing "Últimas notas" heading).
12. The board focuses Excalidraw's container on a canvas press and after a rail click: with `handleKeyboardGlobally=false` Excalidraw never takes focus itself, so letter shortcuts would otherwise not work after a click.
13. The 8.5 MB bundle (esbuild IIFE inlines every Excalidraw locale) and Excalidraw's stylesheet load lazily the first time a board opens.
14. **CSP: unchanged.** Paste, drop, thumbnails and exports worked under the existing policy.
15. Approved-exception candidates: `src/main/store.cjs` was already above 350 lines (378) before this work and now has 383 (board hooks: type, migration call, empty board, thumbnail flag, body refusal). `tests/smoke/boards.cjs` is 280 lines (smoke driver; above the 250-line evaluation threshold).
16. `tests/app-smoke.js` expected six sidebar sections; it now expects seven (Quadros), as this specification requires.
